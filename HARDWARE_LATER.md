# SmartCart Cart Camera Hardware Protocol Specification (`/ws/device`)

This document defines the WebSocket communication protocol for physical cart overhead cameras (e.g. ESP32-CAM, Raspberry Pi, smartphone, or laptop webcam).

---

## 1. Connection & Endpoint

- **WebSocket URL**: `ws://<server_host>:<port>/ws/device` (or `wss://...` over TLS/HTTPS)
- **Strict Query String Policy**: The device token **MUST NEVER** be passed in the URL (e.g. `/ws/device?token=...` is strictly forbidden and rejected immediately with close code `4003`).
- **Concurrency Policy**: Exactly **one device connection per cart**. If a new device connects with a valid token for an already connected cart, the server accepts the new connection and cleanly terminates the previous connection with close code `4009` (`Replaced by new device connection`). This prevents stale connections from locking out rebooted hardware.

---

## 2. Authentication Handshake (First-Message Auth)

1. The client opens the WebSocket connection to `/ws/device`.
2. The server accepts the initial TCP/WebSocket handshake and starts a **5.0-second timer**.
3. The client **MUST** send an `auth` message as its first transmission:
   ```json
   {
     "type": "auth",
     "token": "CART003_SECRET_TOKEN_2026"
   }
   ```
4. The server computes `SHA-256(token)` and looks up the cart in the database.
   - The cart identity (`cart_id`, `cart_number`) is derived **solely from the token hash**. The client does not specify which cart it claims to be.
5. If valid and enabled:
   The server responds with:
   ```json
   {
     "type": "auth_ok",
     "cart_id": "c3e1b789-9a2c-4e8a-bf90-3456789abcde",
     "cart_number": "CART-003",
     "camera_status": "ONLINE",
     "server_time": "2026-11-10T13:45:00.000Z"
   }
   ```
   The cart's camera status immediately switches to `ONLINE`.

---

## 3. WebSocket Close Codes

| Code | Reason | Description |
| :--- | :--- | :--- |
| `4001` | `Auth timeout` / `Malformed auth message` | No valid `auth` message received within 5.0 seconds of connection. |
| `4003` | `Token in URL forbidden` | Client attempted to pass `?token=...` in query string or headers. |
| `4004` | `Unknown device token` | The provided token's SHA-256 hash was not found in the cart registry. |
| `4005` | `Cart disabled by store staff` / `Token regenerated` | The cart is currently disabled, or the token was regenerated by an administrator. |
| `4009` | `Replaced by new device connection` | A second connection authenticated for this cart, gracefully superseding the prior session. |
| `4013` | `Frame exceeds 200 KB limit` | Client payload exceeded size limits. |

## 4. Message Types & Payload Specifications

### 4.1 Heartbeat (`heartbeat`)
Must be sent every **5 seconds** to maintain `ONLINE` status. If no frame or heartbeat arrives for **15 seconds**, the server watchdog marks the cart `OFFLINE`.

- **Client Request**:
  ```json
  {
    "type": "heartbeat",
    "battery": 95,
    "timestamp": 1794318300000
  }
  ```
- **Server Response**:
  ```json
  {
    "type": "heartbeat_ack",
    "cart_number": "CART-003",
    "timestamp": "2026-11-10T13:45:05.000Z"
  }
  ```

---

### 4.2 Camera Frame (`frame`)
Transmitted only during active motion at **2 to 5 FPS**, plus **one keep-alive frame every 10 seconds** during quiet periods.

- **Image Specs**:
  - Resolution: ~640 × 480 pixels
  - Format: JPEG (`image/jpeg`)
  - Quality: 0.70 (balanced for low latency and compression)
  - Max Size: **200 KB** (larger frames are rejected with `frame_error`)
  - Throttling: Max 10 FPS server processing cap

- **Client Request (Normal Basket View)**:
  ```json
  {
    "type": "frame",
    "format": "jpeg",
    "data": "data:image/jpeg;base64,/9j/4AAQSkZJRg...",
    "hand_present": false,
    "face_present": false,
    "motion_level": 0.42,
    "timestamp": 1794318301200
  }
  ```

- **Client Request (Privacy Redacted - Face Detected)**:
  > [!IMPORTANT]
  > When the in-device or browser vision detector identifies a human face, **the image data MUST be withheld** (`data: null`). Only metadata flags are sent.
  ```json
  {
    "type": "frame",
    "format": "jpeg",
    "data": null,
    "hand_present": false,
    "face_present": true,
    "motion_level": 0.15,
    "privacy_redacted": true,
    "timestamp": 1794318302000
  }
  ```

- **Server Response**:
  ```json
  {
    "type": "frame_ack",
    "status": "RECEIVED",
    "frames_per_minute": 24
  }
  ```

---

### 4.3 Empty Cart Reference Frame (`reference_frame`)
Sent when store staff taps "Capture empty cart reference" or when the cart initializes in an empty state.

- **Client Request**:
  ```json
  {
    "type": "reference_frame",
    "format": "jpeg",
    "data": "data:image/jpeg;base64,/9j/4AAQSkZJRg...",
    "is_reference": true,
    "timestamp": 1794318300500
  }
  ```

- **Server Response**:
  ```json
  {
    "type": "reference_frame_ack",
    "status": "SAVED_AS_REFERENCE"
  }
  ```

---

### 4.4 Motion Sensor Event (`motion`)
Optional digital PIR / motion sensor signal from ESP32 GPIO.

- **Client Request**:
  ```json
  {
    "type": "motion",
    "state": "start"
  }
  ```
- **Server Response**:
  ```json
  {
    "type": "motion_ack",
    "state": "start"
  }
  ```

## 6. Implementation Notes for ESP32-CAM / Phone Hardware

1. **Memory Bounds**: Use PSRAM on ESP32-CAM for JPEG frame buffers (`fb->buf`). Limit capture size to 640x480 (`FRAMESIZE_VGA`) and JPEG quality to 10-12 (which maps to 0.70).
2. **Reconnection**: Implement exponential backoff: 1s, 2s, 4s, up to 10s max.
3. **Privacy**: ESP32-CAM hardware with localized face detection (ESP-WHO) must clear the JPEG buffer before transmitting when a face bounding box is present.
